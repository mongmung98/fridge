# 멍꼬북 블로그 반자동 작성 시스템 — 설계 문서

- 작성일: 2026-11-15
- 상태: 사용자 승인 대기 → 승인 후 작업 계획서(plan) 작성
- 보관 위치(사용자 PC): `<ROOT>\_system\docs\` 에 이 파일을 넣고, PC의 Claude Code가 읽고 이어서 작업한다.
- 원본 요구사항: 사용자가 작성한 「멍꼬북 블로그 반자동 작성 시스템 — Claude Code 시작 프롬프트」(이하 '원 프롬프트'). **같은 폴더의 `원프롬프트_멍꼬북_ClaudeCode_시작프롬프트.md`로 함께 보관**한다(§번호 참조는 이 파일 기준). 이 문서는 원 프롬프트 + 대화에서 확정한 결정을 합친 것이며, 충돌 시 **이 문서가 우선**한다.
- '프로젝트 지침 v2'(일기주제 B-0 포함)는 사용자 PC의 `_system\samples\`에만 있다 → `/멍꼬북 일기주제`는 PC에서 그 문서를 읽은 뒤 확정한다(계획에는 자리만 잡음).

---

## 1. 목적과 이유

네이버 블로그 '멍꼬북' 운영자(비개발자)가 **주제 폴더 하나(사진·영상·memo) + 한 줄 명령**으로
① 자기 문체의 초안을 얻고 ② 네이버 해당 게시판에 **임시저장**까지 되게 하는 것.
글을 쓰는 데 드는 반복 노동(사진 정리, 서식 입히기, 정보 박스, 에디터 입력)을 줄이되,
**최종 검수와 발행은 사용자가 직접** 한다. 결과물은 '사람이 직접 겪고 쓴 글'이어야 한다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 폴더 생성 → 사진 처리 → 초안(md/html/json) → 검사기 → 네이버 임시저장 1건
- 모드별(A 리뷰 / B 일기 / C 레시피 / D 영화) 멍꼬북 문체 재현
- `/멍꼬북` 명령 하나로 전체 사용 (Claude Code 스킬)

**비목표 (이번 범위 아님)**
- 백업 (사용자가 요청할 때 재검토. 위험 메모: 원본 사진이 SSD 한 곳에만 있음 — 폰에서 삭제함)
- 인스타 릴스/피드 (2차. 대화에서 ffmpeg 기반 가능성만 확인함)
- 도서·커피·숙소·장소·디지털드로잉 등 다른 게시판 (사용자가 나중에 글을 주면 지침 추가)
- 얼굴/번호판 자동 블러 (알림만)

**반목표 (이렇게 되면 기술적으로 동작해도 실패)**
- 발행 버튼을 누름 / 여러 글을 연속·대량 게시함
- 비밀번호를 파일·코드·로그에 저장함
- 원본 사진·영상을 수정·이동·삭제함
- memo에 없는 가격·시간·수치를 지어냄
- 네이버 템플릿에 들어 있던 **예전 글 문장이 새 글에 남은 채** 임시저장됨
- 사진 자리에 "사진 설명을 입력하세요" 같은 placeholder가 남음

## 3. 환경과 제약

- OS: **Windows**. 작업 루트(`ROOT`):
  `J:\3. 블로그\멍꼬북 블로그_요리, 맛집, 장소, 도서, 영화리뷰, 디지털드로잉, 일상\`
  - 경로에 **공백·쉼표·한글**이 있음 → 모든 스크립트는 경로를 인자로 받을 때 따옴표 처리, UTF-8 (`PYTHONUTF8=1` 또는 `encoding="utf-8"` 명시), `pathlib` 사용.
  - 루트 경로는 `_system\config.json`의 `root`에 저장하고 하드코딩하지 않는다(드라이브 문자가 바뀔 수 있음).
- 실행 장소: 사용자 PC의 **Claude Code 데스크톱 앱**을 ROOT에서 연다. (설계·계획은 클라우드 세션에서 작성, 구현·시연은 PC에서)
- 사용자는 비개발자: 설치 명령은 복붙 가능한 한 줄씩, 전문용어는 쉬운 말로, 대화는 한국어.
- 필요한 설치(구현자가 PC에서 안내): Python 3.12(winget), `pillow`, `pillow-heif`, Chrome + **Claude in Chrome 확장**(Claude Code와 연동). ffmpeg는 이번 범위에서 불필요.

## 4. 접근 방식 (Approaches)

| 방식 | 내용 | 결론 |
|---|---|---|
| **① Claude Code 스킬 + 작은 Python 스크립트** | 판단이 필요한 일(memo 해석, 사진 보고 배치, 글쓰기, 사실 확인, 브라우저 조작)은 Claude가, 결정적(매번 같아야 하는) 일(사진 변환, 검사기, html 렌더, 상태 기록)은 스크립트가 | **채택** — 사용자는 방법을 맡김, Claude가 결정 |
| ② 독립 Python 앱이 Claude API 호출 | 별도 API 키·요금, 사진 판단 품질 저하 | 기각 |
| ③ 스크립트 없이 매번 Claude 수작업 | 결과·검사가 매번 달라짐 | 기각 |

**네이버 업로드 방식** (사용자가 선택): ① 반자동 / **② Claude가 내 크롬 조작(채택)** / ③ Playwright 스크립트(②가 안정된 뒤 필요 시 검토).
②가 실패하면 항상 ①로 폴백: `draft.html`을 열어 복사·붙여넣기 + `_output\photos` 순서대로 업로드 안내.

## 5. 폴더 구조

```
<ROOT>\
├─ 01_맛집\
│   └─ 20261115 단양원조마늘순대\       ← 'YYYYMMDD 주제' (사진 촬영일)
│       ├─ 원본 사진(jpg/jpeg/heic/png) · 영상(mp4/mov)   ← 읽기 전용 취급
│       ├─ memo.txt
│       └─ _output\
│           ├─ photos\       업로드용 사진 (01_xxx.jpg …)
│           ├─ draft.md      사람이 읽는 초안
│           ├─ draft.html    블로그처럼 보이는 미리보기
│           ├─ draft.json    에디터 입력용 블록 구조
│           ├─ report.json   검사기 결과
│           └─ status.json   진행 상태
├─ 02_레시피\  03_일기\  04_영화\  05_여행\
└─ _system\
    ├─ config.json           root 경로, 기본값(글자 15pt, 사진 20장 등)
    ├─ categories.json       폴더 ↔ 네이버 게시판 ↔ 모드 ↔ 템플릿 매핑
    ├─ style\                style_guide.md, cliches.txt(금지 문구)
    ├─ samples\              기존 블로그 PDF 5개 + 프로젝트 지침 v2 (사용자가 넣음)
    ├─ templates\            memo.txt 양식, 모드별 초안 골격, naver\(템플릿 원문 스냅샷)
    ├─ scripts\              Python 코드
    ├─ docs\                 이 설계 문서, 작업 계획서
    └─ logs\                 diary_counter.json, run.log
```

- 폴더명 날짜 ≠ 사진 EXIF 촬영일이면 **경고만**, 폴더명 우선.
- `/멍꼬북 새주제 맛집 단양원조마늘순대` → `01_맛집\YYYYMMDD 단양원조마늘순대\` + memo.txt 생성. 날짜는 (폴더에 이미 사진을 넣어둔 경우) 가장 이른 EXIF 촬영일, 없으면 오늘.

## 6. 게시판 매핑 (`_system\categories.json`)

| 로컬 폴더 | 네이버 카테고리 | 모드 | 네이버 '내 템플릿' |
|---|---|---|---|
| `01_맛집` | 소비기록 > 맛집 | A 리뷰 | `[맛집 양식]` |
| `02_레시피` | 취미기록 > 요리 | C 레시피 | `[요리 양식] 닭볶음탕 레시피 …` |
| `03_일기` | 일상기록 > **소소한 하루** | B 일기 | `[일기 양식] #18 매월 25일, 매달 받는 안정감` |
| `04_영화` | 일상기록 > 주말의 영화 | D 영화 | `[영화 양식] 영화 〈얼굴〉 후기 …` |
| `05_여행` | 여행일기 > 호주_여행일기 / 스페인_여행일기 / 대만_여행일기 (memo `게시판:`으로 지정, 없으면 질문) | A 리뷰 | `[맛집 양식]` (구현자 판단, 사용자 확인) |
| **테스트** | 소비기록 > **외쿡 맛집** (비공개) | — | — |

- '일상기록 > 소소한 하루일기'는 **개인 메모용 — 시스템이 절대 사용하지 않음**.
- `[카페 양식]`이 존재하지만 커피 게시판은 이번 범위 밖 (매핑에 비활성으로만 기록).
- memo의 `게시판:` 값이 있으면 폴더보다 우선.

## 7. memo.txt

원 프롬프트 §2 양식 그대로 (게시판/방문·촬영일/함께한 사람/한 줄 느낌/좋았던 점/아쉬운 점/별점/재방문/꼭 넣을 내용/뺄 내용/대표사진/제목 키워드/기타 요청).
- 자유 서술도 Claude가 해석한다(양식은 권장). 스크립트는 `키: 값` 줄만 보조 추출.
- 빈 칸은 지어내지 않고 본문에 `[○○ 확인 필요]` → 초안 끝에 질문 목록으로 한 번에 물음.

## 8. 사진·영상 처리

**스크립트 (`process_photos.py`)** — 원본은 읽기만 함
1. jpg/jpeg/png/heic 수집, EXIF 촬영일 읽기 (없으면 파일 수정시각)
2. `exif_transpose`로 방향 바로잡기 → HEIC는 JPG 변환 → 긴 변 최대 2000px (작으면 그대로)
3. **EXIF 전체 제거(GPS 포함)** 후 `_output\photos\`에 저장
4. 촬영 시간순 정렬, `01_`, `02_` … 접두. memo의 대표사진이 있으면 01
5. 결과 목록(원본명 ↔ 새 이름 ↔ 촬영시각 ↔ 크기)을 status.json에 기록
- 영상: 복사·변환하지 않음. 촬영시각 순서에 끼워 본문 위치만 지정. **300MB 이상이면 알림**(구현자가 기준 조정 가능).

**Claude 판단**
- 사진을 직접 보고 섹션(외관/매장/메뉴판/음식/영수증 등)에 배치.
- 흔들림·중복은 후보에서 제외하되 **제외 목록을 알려줌**.
- 기본 **최대 20장**. 20장을 넘는데 뺄 사진이 없다고 판단되면 임의로 줄이지 않고 "추가 후보 N장"으로 제안.
- **사람 얼굴(사용자·아내 포함 누구든)이나 차량 번호판이 보이면** 사진 번호와 함께 알림. 블러는 하지 않음.

## 9. 글쓰기 규칙

원 프롬프트 §3 전체를 따른다. 1단계 첫 작업으로 `_system\samples\`의 실제 글을 읽고 §3 규칙과 합쳐 `_system\style\style_guide.md`를 만들어 **사용자 확인을 받는다**.

추가로 확정된 것:
- **D 영화**: 원 프롬프트의 D 템플릿을 새로 제안하지 않고, 사용자의 네이버 `[영화 양식]` 구조를 기준으로 삼는다(1단계에서 Chrome으로 템플릿 원문을 열어 구조를 추출하거나, 사용자가 해당 PDF/텍스트를 samples에 넣음 — 구현자가 가능한 쪽으로).
- 모드별 구조는 해당 네이버 템플릿의 섹션 순서와 일치시킨다(§11 템플릿 교체 방식 때문에).
- **B 일기 번호**: '소소한 하루' 게시판의 마지막 `#번호` + 1. `_system\logs\diary_counter.json`에 저장. 처음 쓸 때 값이 없으면 사용자에게 마지막 번호를 묻는다. 임시저장 성공 시 증가(초안만 만들고 버린 경우 증가하지 않음).
- `/멍꼬북 일기주제`: 원 프롬프트가 말한 '프로젝트 지침 B-0'은 samples의 프로젝트 지침 v2 문서에 있음 — 구현자가 읽고 그대로 따른다.
- 사실 정보(주소·영업시간·전화·주차)는 웹 검색으로 확인, 출처 URL을 status.json `sources`에 기록. 확인 못 하면 `[확인 필요]`.

## 10. 서식 규칙과 초안 포맷

- 본문 **15pt** (네이버 에디터 기본값과 같음. 샘플 확인 후 16이 맞다면 사용자 확인 후 변경).
- 원 프롬프트 §4 표 그대로: 중요=굵게, 강조=굵게+밑줄+배경 `#FFF5B1`(문단당 1회, 글 전체 3~5회), 개인 생각=기울임, 핵심정보=인용구, 섹션 제목=소제목, 섹션 구분=구분선.
- 맛집·여행 글은 에디터 **'장소'(지도) 첨부** 블록을 포함한다.

**draft.json (구현자가 세부 확정, 최소 스키마)**
```json
{
  "mode": "A",
  "category": "소비기록 > 맛집",
  "template": "[맛집 양식]",
  "title": "추천 제목",
  "title_candidates": ["…", "…", "…"],
  "tags": ["단양맛집", "…"],
  "place": {"name": "단양원조마늘순대", "query": "단양원조마늘순대"},
  "blocks": [
    {"type": "quote", "spans": [{"text": "📍 위치: …"}]},
    {"type": "text", "spans": [{"text": "안녕하세요, 멍꼬북입니다 🐢"}]},
    {"type": "divider"},
    {"type": "subtitle", "text": "1. 음식점 기본 정보"},
    {"type": "list", "items": [[{"text": "상호: …"}]]},
    {"type": "image", "file": "photos/03_xxx.jpg"},
    {"type": "video", "file": "IMG_1234.MOV"},
    {"type": "text", "spans": [{"text": "정말", "bold": true, "underline": true, "bg": "#FFF5B1"}, {"text": "…", "italic": true}]}
  ],
  "open_questions": ["[영업시간 확인 필요] …"]
}
```
- `draft.md`, `draft.html`은 `draft.json`에서 **스크립트로 생성**(단일 원천). html은 실제 블로그처럼(15pt, 인용구 박스, 구분선, 노란 배경) 보이게, 이미지는 `_output\photos` 상대경로.

## 11. 검사기 (`validate.py` → `report.json`)

초안 생성 후 자동 실행, 미달 항목이 있으면 Claude가 고쳐서 재검사(**최대 3회**, 이후엔 남은 문제를 사용자에게 보고).

1. 모드별 필수 요소 — A: 핵심박스·기본정보·총평·요소별 별점·재방문·추천/비추 / B: `#소제목`·`오늘 저녁 메뉴 :`·`#YYMMDD` 날짜 태그·`#하루일기 #일기 #소소한하루` / C·D: 각 템플릿 섹션
2. 말투 — 일기에 존댓말(`~습니다/~요` 종결) 섞임, 리뷰에 반말 과다
3. 노란 강조 3~5회·문단당 1회, 기울임 사용 위치(Claude 자기 점검 항목으로 report에 기록)
4. 금지 문구 — placeholder("사진 설명을 입력하세요" 등), `_system\style\cliches.txt` 목록
5. `[확인 필요]` 개수
6. **지어낸 사실** — 본문의 숫자(가격·시간·수치)가 memo, 확인된 출처(status.sources), 사진에서 읽은 메뉴판/영수증 기록 중 하나에 근거가 있는지 대조, 근거 없는 숫자 목록화
7. **노출 점검 6항목** (사용자 승인 — 노출을 보장하지 않는 권장 기준)
   1. 제목 앞부분에 핵심 키워드(지역+메뉴/장르)
   2. 같은 핵심 키워드 본문 3~5회 (과다 반복 경고)
   3. 맛집·장소 글 '장소(지도)' 블록 포함
   4. 직접 찍은 사진 10~20장 (+영상 있으면 1개 이상 배치)
   5. 본문 공백 제외 1,500~2,500자
   6. 태그 5~10개(핵심 키워드+지역+상호), 소제목에 키워드 자연 포함
   - B 일기는 5·6·1·2 기준을 완화(일기는 SEO 강제 금지 — 원 프롬프트 §3)

## 12. 네이버 임시저장 (② Claude in Chrome)

**원칙**: 발행 금지, 임시저장만 / 명령받은 글 1개만 / 사람 속도로 / 비밀번호 미취급(사용자가 이미 로그인한 크롬 사용) / 로그인·캡차·2단계 인증 화면이 뜨면 멈추고 사용자 호출 / **첫 성공은 반드시 테스트 게시판(외쿡 맛집, 비공개)**.

**순서**
1. 사전 확인 표(제목/게시판/사진 수/영상 수/강조 횟수/[확인 필요] 개수) → 사용자 "진행" 확인
2. status.json에 `uploaded_draft: true`가 이미 있으면 중복 임시저장 여부를 먼저 묻는다
3. 글쓰기 열기 → 카테고리 선택
4. 템플릿 `내 템플릿 > [해당 양식]` 불러오기 (사용자 결정 (가))
5. 섹션 단위로 내용 교체: 제목, 핵심박스, 각 소제목/본문, 사진 삽입(`_output\photos` 순서), 영상, 장소, 태그
6. **템플릿 잔존 문장 검사**: 처음 템플릿을 쓸 때 원문 텍스트를 `_system\templates\naver\<양식명>.txt`로 스냅샷 저장. 임시저장 직전 에디터 전체 텍스트를 읽어 스냅샷 문장(고정 문구 화이트리스트 제외: 인사말, 번호 소제목 틀 등)이 남아 있으면 **멈추고 보고**
7. 임시저장 클릭 → 저장 확인 화면 캡처 → `_output\saved_screenshot.png`
8. status.json: `uploaded_draft: true, uploaded_at, category, screenshot`

**위험과 폴백**
- 사진 업로드: 확장 프로그램이 로컬 파일 업로드를 못 하거나 불안정하면 → Claude가 글을 다 넣고, 사진은 사용자가 `_output\photos`에서 지정 위치로 끌어다 놓도록 단계별 안내(① 반자동 일부 적용).
- 서식(배경색·밑줄) 입력이 불가능한 경우 → 해당 부분 목록을 사용자에게 보고.
- 어느 단계든 실패 시: 지금까지 된 상태로 **임시저장만** 하고(가능하면) 이유 + ①방식 안내.
- 2단계 첫 작업은 위 조작들이 실제로 되는지 **테스트 게시판에서 시험**하는 것.

## 13. 명령 (`/멍꼬북` 스킬)

```
/멍꼬북 새주제 맛집 단양원조마늘순대
/멍꼬북 초안 01_맛집/20261115 단양원조마늘순대
/멍꼬북 수정 01_맛집/20261115 단양원조마늘순대 "아쉬운 점 좀 더 솔직하게"
/멍꼬북 임시저장 01_맛집/20261115 단양원조마늘순대 [게시판 이름]
/멍꼬북 일기주제
/멍꼬북 상태        ← 폴더별 진행 상태 표(초안/검사/임시저장 여부, [확인 필요] 수)
```
- 스킬은 ROOT의 `.claude\skills\` (프로젝트 스킬)에 둔다.
- **주의**: 스킬/명령 이름에 한글이 허용되는지 구현자가 PC에서 먼저 확인. 안 되면 영문 이름(예: `mkb`) + 설명에 '멍꼬북' 트리거를 넣고 사용자에게 알린다.
- `수정`은 draft.json을 고친 뒤 md/html 재생성 + 검사기 재실행.
