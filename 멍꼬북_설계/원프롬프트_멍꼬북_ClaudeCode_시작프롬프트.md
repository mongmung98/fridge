# 멍꼬북 블로그 반자동 작성 시스템 — Claude Code 시작 프롬프트

> 사용법: Claude Code(데스크톱 앱 또는 터미널)를 SSD의 작업 폴더에서 열고, 아래 `===` 사이 전체를 첫 메시지로 붙여넣으세요.
> 참고 자료(기존 블로그 PDF 5개, 프로젝트 지침 v2)는 `_system/samples/`에 넣어두면 Claude Code가 직접 읽습니다.

===

## 0. 너의 역할과 진행 방식

너는 내 네이버 블로그 **'멍꼬북'** 의 작성 파이프라인을 만드는 개발 파트너야.
목표는 **"주제 폴더 하나 + 한 줄 명령 → 내 톤의 초안 → 네이버 해당 게시판에 임시저장"** 까지를 만드는 것.
**발행은 절대 하지 않는다. 임시저장까지만.** 최종 검수·발행은 내가 직접 한다.

진행 순서(꼭 지켜줘):
1. `superpowers:brainstorming` 스킬로 아래 '확인할 것(§9)'을 **한 번에 하나씩** 물어보고 설계를 확정해.
2. 설계 문서 승인 후 `superpowers:writing-plans`로 단계별 계획을 쓰고, `executing-plans`로 실행해.
3. 각 단계가 끝날 때마다 `superpowers:verification-before-completion` 기준으로 **실제로 돌려보고** 결과를 보여줘.
4. 완성되면 `skill-creator`로 이 작업 전체를 **`/멍꼬북` 스킬**로 묶어줘.
5. 나는 비개발자야. 명령어·설치는 복붙할 수 있게 한 줄씩 주고, 전문용어는 쉬운 말로 풀어줘. 대화는 한국어로.

## 1. 폴더 구조 (SSD)

```
[SSD]:\멍꼬북블로그\
├─ 01_맛집\
│   └─ 20261115 단양원조마늘순대\      ← '사진촬영날짜(YYYYMMDD) 띄어쓰기 포스팅주제'
│       ├─ (사진들: jpg/heic/png)
│       ├─ (동영상들: mp4/mov)
│       ├─ memo.txt                    ← 내 느낌·후기·요청사항
│       └─ _output\                    ← 시스템이 만드는 결과물(자동 생성)
│           ├─ photos\                 ← 변환·리사이즈·정렬된 업로드용 사진
│           ├─ draft.md                ← 사람이 읽는 초안
│           ├─ draft.html              ← 서식 미리보기(브라우저로 열기)
│           ├─ draft.json              ← 에디터 입력용 블록 구조
│           └─ status.json             ← 진행 상태 기록
├─ 02_레시피\
├─ 03_일기\
├─ 04_영화\
├─ 05_여행\        (필요 시 추가)
└─ _system\
    ├─ style\       ← 톤·구조 규칙(아래 §3, §4를 파일로 저장)
    ├─ samples\     ← 기존 블로그 글 PDF/텍스트 (톤 학습용)
    ├─ templates\   ← memo.txt 양식, 모드별 템플릿
    ├─ scripts\     ← 코드
    └─ logs\
```

- 1단계 작업으로 위 폴더 트리와 `memo.txt` 양식을 만들어줘. 폴더 생성 보조 명령도: `새주제 맛집 단양원조마늘순대` → 사진 EXIF 날짜가 없으면 오늘 날짜로 폴더 생성.
- 폴더명 날짜가 사진 EXIF 촬영일과 다르면 경고만 하고 폴더명 우선.

## 2. memo.txt 양식 (자동 생성, 내가 채움)

```
게시판: 맛집            # 비우면 상위 폴더로 판단
방문/촬영일: 2026-11-15
함께한 사람: 아내
한 줄 느낌:
솔직 후기(좋았던 점):
솔직 후기(아쉬운 점):
별점(맛/분위기/서비스/가성비/총점):
재방문 의사:
꼭 넣어줄 내용:
빼줄 내용:
대표사진(파일명):
제목에 넣고 싶은 키워드:
기타 요청:
```
- 비어 있는 칸은 지어내지 말고 본문에 `[○○ 확인 필요]`로 남기고, 마지막에 한 번에 물어봐.
- 메모가 자유 서술이어도 읽을 수 있어야 함(양식은 권장일 뿐).

## 3. 글쓰기 규칙 (멍꼬북 톤)

`_system/samples/`의 실제 글을 먼저 읽고, 아래 규칙과 합쳐 `_system/style/style_guide.md`로 정리해서 내게 확인받아줘.

**모드 판별**: 상위 폴더 → 맛집/여행=A(리뷰), 일기=B, 레시피=C, 영화=D

**공통**
- 시그니처 🐢, 상황별 😆 😁 🥰 / 아내와의 소소한 일상을 자연스럽게
- 좋은 점·아쉬운 점 둘 다 솔직하게. 과장광고·클리셰·내용 없는 미사여구 금지
- 가보지 않은/확인 안 된 정보 단정 금지 → `[확인 필요]`
- 사진 자리에 "사진 설명을 입력하세요" 같은 텍스트 절대 넣지 않기

**A 리뷰 / C 레시피 / D 영화 (존댓말 기본, 구어 포인트에서 반존대)**
- 맨 위 **인용구 블록 = 핵심정보 박스** (이모지 머리 3~5줄. 예: 📍위치 / 🍗메뉴·가격 / 👍한줄평 / 🐢픽업·주차 팁)
- 오프닝 "안녕하세요, 멍꼬북입니다 🐢" + 방문 계기 2~3줄
- 소제목은 번호형("1. 음식점 기본 정보", "2. 외관&매장 분위기" …), 소제목 사이 **구분선**
- 기본 정보는 글머리표 목록(상호/주소/영업시간/주차/대기/주문 방식/포장·택배)
- 마무리: 멍꼬북 총평 / 요소별 별점 / 재방문 의사 / 이런 분께 추천·비추 → 마무리 인사
- 제목 후보 3~5개 + 추천 1개 (맨 앞에 핵심 키워드: 지역+카테고리+특징)
- 영업시간·주소 등 사실 정보는 웹으로 확인하고 출처를 status.json에 기록, 확인 못 하면 `[확인 필요]`

**B 일기 (혼잣말 평서체, 존댓말 아님)**
- 제목 형식: `#번호 제목` (예: `#22 과욕은 금물, 색다른 경험은 환영`) — 번호는 직전 일기 +1 (logs에 기록)
- 생각 덩어리마다 `#해시태그형_소제목`(예: `#과욕은_금물`), 사이사이 구분선
- 하루 사건 → 성찰 → 작은 다짐 / 가벼운 자조 OK (ㅎㅎ)
- 필수 마무리: `오늘 저녁 메뉴 : ○○` + 음식/하늘 사진 + 해시태그 `#하루일기 #일기 #소소한하루 #YYMMDD` + 그날 키워드
- SEO 박스·존댓말 강제 금지

**D 영화 (신규 — 초안 템플릿을 제안해서 확인받기)**
- 핵심박스(제목/장르/러닝타임/관람처/한줄평/별점) → 보게 된 계기 → 스포 없는 줄거리 → 좋았던 점 → 아쉬운 점 → 인상 깊은 장면(내 생각) → 총평·추천/비추
- 포스터·스틸컷은 공식 이미지 대신 **내가 찍은 사진**(티켓, 상영관, 팝콘 등)만 사용

## 4. 서식 규칙 (네이버 스마트에디터 ONE 기준)

| 용도 | 서식 |
|---|---|
| 본문 | 15 또는 16pt (§9에서 확정) |
| 중요한 부분 | **굵게** |
| 강조하고 싶은 부분 | **굵게 + 밑줄 + 옅은 노란색 글자배경색** (문단당 최대 1회, 글 전체 3~5회) |
| 개인적인 생각 | *기울임* |
| 핵심정보 박스 | 인용구 블록 |
| 섹션 제목 | 소제목 블록 |
| 섹션 구분 | 구분선 |

- `draft.json`은 블록 배열로: `{type: quote|subtitle|text|image|video|divider|list, ...}`, 텍스트는 span 단위로 `{text, bold, underline, italic, bg:"#FFF5B1"}` 식.
- `draft.md`에서는 표기 규칙: `**굵게**`, `<u>**강조**</u>==배경==`, `*기울임*` 등 — 미리보기 `draft.html`은 실제 블로그처럼 보이게.
- 내 **스마트에디터 '내 템플릿'** 을 쓸지 여부는 §9에서 확인. 쓴다면 템플릿 불러오기 → 자리 채우기 방식, 아니면 블록 직접 생성.

## 5. 사진·영상 처리

- HEIC → JPG 변환, 긴 변 최대 약 2000px로 리사이즈(원본은 절대 수정·삭제하지 않음)
- **EXIF 위치정보(GPS) 제거** 후 업로드용으로 저장
- 촬영 시간순 정렬 → 파일명 앞에 순번(01_, 02_…) / 대표사진은 memo 지정 사진을 01로
- Claude가 사진을 직접 보고 각 사진이 어느 섹션(외관/메뉴/음식/영수증 등)에 맞는지 배치. 흔들림·중복 사진은 후보에서 빼되 목록으로 알려주기
- (선택) 타인 얼굴·차량번호판 블러 — §9에서 확인
- 동영상은 그대로 두고 본문 위치만 지정. 용량이 크면 알려주기

## 6. 네이버 임시저장 (업로드 단계)

**원칙**
- 발행 버튼은 누르지 않는다. **임시저장만**. 한 번에 글 1개씩, 사람처럼 천천히.
- 네이버 약관은 자동화 수단을 이용한 게시를 제한하고 있으니, 대량·반복 게시 기능은 만들지 않는다. 내가 명령한 그 1개 글만 처리.
- **비밀번호를 파일·코드·로그에 평문으로 저장하지 않는다.** 1순위: 내가 처음 한 번만 직접 로그인하고 그 브라우저 로그인 상태를 재사용. 2순위(내가 원할 때만): Windows 자격 증명 관리자(keyring)에 저장. 2단계 인증·캡차가 뜨면 멈추고 나를 불러.

**방식 — 아래 3가지를 비교 설명하고 내가 고르게 해줘 (내 추천은 ②로 시작 → 안정되면 ③ 검토)**
1. **반자동**: 초안 HTML을 열어 내가 복사→에디터 붙여넣기, 사진만 내가 업로드. 가장 안전, 손이 가장 많이 감.
2. **Claude가 내 브라우저 조작** (Claude in Chrome 확장 또는 Claude 데스크톱 앱 내장 브라우저): 이미 로그인된 내 브라우저에서 글쓰기 → 카테고리 선택 → 블록 입력 → 사진 업로드 → 임시저장. 진행 화면을 내가 볼 수 있음. 느리지만 화면이 바뀌어도 적응력이 좋음.
3. **Playwright 스크립트**: 로그인 상태가 저장된 전용 크롬 프로필로 실행. 빠르고 반복 가능하지만, 네이버 에디터 화면이 바뀌면 깨질 수 있음 → 실패 시 자동으로 ①로 폴백하고 이유 알려주기.

**공통 처리**
- 게시판(카테고리) 이름 매핑표: `_system/categories.json` (§9에서 실제 이름 받기)
- 업로드 전 마지막 체크: 제목/게시판/사진 수/서식 요약을 보여주고 "진행?" 확인
- 완료 후 status.json에 `uploaded_draft: true, 시간, 임시저장 확인 스크린샷 경로` 기록. 같은 폴더를 다시 요청하면 중복 임시저장 전에 물어보기
- 테스트는 반드시 **비공개 테스트 게시판**에서 먼저

## 7. 내가 쓸 명령 (최종 형태)

```
/멍꼬북 초안 01_맛집/20261115 단양원조마늘순대
/멍꼬북 수정 01_맛집/20261115 단양원조마늘순대  "아쉬운 점 좀 더 솔직하게"

/멍꼬북 일기주제          ← 프로젝트 지침 B-0처럼 오늘의 주제 1개 제안
/멍꼬북 상태              ← 폴더별 진행 상태 표
```

## 8. 초안 검증기 (validator)

초안 생성 후 자동 점검하고 미달이면 스스로 고쳐서 다시 점검:
- 모드별 필수 요소 존재(A: 핵심박스·기본정보·총평·별점·추천/비추 / B: 평서체·#소제목·오늘 저녁 메뉴·날짜 태그)
- 일기에 존댓말 섞임 여부 / 리뷰에 반말 과다 여부
- 노란 강조 남용(3~5회), 기울임은 개인 생각에만
- 금지 문구(사진 설명 placeholder, 클리셰 목록) 검출
- `[확인 필요]` 개수 리포트
- 메모에 없는 사실(가격·시간·수치)을 지어냈는지 대조

## 9. 시작 전에 나에게 확인할 것 (brainstorming에서 하나씩)

1. 운영체제(Windows/Mac)와 SSD 드라이브 문자/경로
2. 본문 글자 크기 15 vs 16 (기존 글 기준 추천해줘)
3. 업로드 방식 ①②③ 중 선택
4. 블로그 카테고리(게시판) 실제 이름 목록 + 비공개 테스트 게시판 유무
5. 스마트에디터 '내 템플릿' 사용 여부와 템플릿 이름
6. 얼굴/번호판 블러 필요 여부, 사진 최대 장수
7. 원본 폴더 백업 방식(SSD 단일 보관 위험) — 클라우드 동기화 여부
8. 인스타 릴스/피드 확장은 2차로 미룰지

## 10. 단계 계획 (권장)

- **1단계 (네이버 없이)**: 폴더/양식 생성 → 사진 처리 → 초안 md/html/json → validator. 실제 폴더 1개(단양원조마늘순대)로 끝까지 시연.
- **2단계**: 선택한 방식으로 테스트 게시판 임시저장 1건 성공 → 실제 게시판.
- **3단계**: `/멍꼬북` 스킬로 패키징, 사용 설명서(`_system/README.md`) 작성.
- **4단계(선택)**: 인스타 확장 — 릴스 컷 구성·자막·해시태그 생성. 사진 몇 장을 짧은 모션 클립으로 만들고 싶으면 Higgsfield MCP 연동(크레딧 유료, 클립당 최대 15초) 검토.
